# 屏幕与线框

所有宽度单位 px。断点用 Tailwind v4 默认值 + 自定义 `3xl`。

---

## 0. 断点与栏位矩阵

| 断点 | 宽度 | 布局 | 侧栏 | 列表 | 阅读区 |
| --- | --- | --- | --- | --- | --- |
| `3xl` | ≥1600 | 三栏 | 280 固定 | 440（可拖 360–640） | flex，内容居中 max 1040 |
| `xl` | 1280–1599 | 三栏 | 260 固定 | 400（可拖 320–560） | flex，min 480 |
| `lg` | 1024–1279 | 三栏 | **56 图标栏**（自动折叠） | 380（可拖 320–480） | flex，min 480 |
| `md` | 768–1023 | 两栏 | Sheet（`[` 或点汉堡打开） | 340 固定 | flex，min 400 |
| `<md` | <768 | 单栏栈式 | Sheet 全屏 | 100% | 全屏推入（独立历史条目） |

**折叠规则（按屏宽从大到小依次触发）**

1. <1600：账号身份色条从 4px 收到 3px；列表不再显示 provider 标签。
2. <1280：侧栏自动折叠为 56px 图标栏（悬停展开为 260px 浮层，`delay 400ms`）。用户手动展开的状态优先于自动折叠，存 `localStorage`。
3. <1024：侧栏完全退出常驻布局，变成 Sheet；列表工具条上出现汉堡按钮。
4. <768：阅读区退出常驻布局。点击列表行 → `navigate` 到 `/mail/:scope/:view/:messageId`，整页替换，顶部出现返回按钮。撰写变全屏。
5. <768 且列表宽 <360：隐藏摘要列。
6. <480：隐藏列表行内的 provider/账号文字标签，只留色条 + avatar。

**栏位分隔与拖拽**：栏之间是 1px `border-border`，拖拽热区 ±3px（视觉 1px，命中 7px）。拖拽把手 `role="separator"` `aria-orientation="vertical"`，支持方向键调整（每次 16px，`Shift` 每次 64px），`Home`/`End` 到最小/最大。宽度存 `localStorage: fm.listWidth`。

**移动端的具体决定**

- 底部 tab 栏 4 项：收件箱 / 未读 / 星标 / 账号。**验证码不做 tab**，它在过滤 chip 里（tab 只放导航，不放筛选）。
- 密度强制 `comfortable`（84px），触控目标 ≥44px。
- 行左滑 → 归档（绿底 + 归档图标）；右滑 → 删除（红底 + 垃圾桶）。滑动阈值 40% 宽或速度 >0.5px/ms；两个手势都进 undo toast。**手势必须有等价按钮**（长按行 → 操作菜单）。
- 阅读页是**真正的路由跳转**，系统返回手势 / 安卓返回键直接可用。
- iOS safe-area：`pb-[env(safe-area-inset-bottom)]`，底部条实际高度 56 + safe area。
- 撰写全屏，`position: fixed inset-0`，顶部 `[取消] 新邮件 [发送]`。
- 键盘弹起时用 `100dvh` 而不是 `100vh`，并给撰写正文加 `scroll-margin-bottom: 96px`。
- **列表与阅读之间不做横向滑动切换**（会和邮件正文的横向滚动打架）。

## 4. 阅读视图细节

见 §1.3 的骨架。以下是三态与边界。

| 情况 | 表现 |
| --- | --- |
| 未选中邮件 | 阅读区显示空态：`Inbox` 轮廓图标 96px `text-muted-foreground/40` + `选择一封邮件` + `或按 J / K 浏览`（`text-xs`）。**不显示广告位、不显示统计卡片。** |
| 正文加载中 | 骨架：主题 2 行 + 发件人行 + 正文 6 条不等宽长条。**不用 spinner** —— 结构已知就用骨架。`animate-pulse`，`prefers-reduced-motion` 下改为静态 `bg-muted`。 |
| 正文加载失败 | 卡片内：`⚠ 无法加载正文` + 错误码 + `[重试]` + `[查看纯文本]`（若 `bodyText` 存在，本地就能渲染，优先提供） |
| 只有纯文本 | 直接在 iframe 里 `white-space: pre-wrap` 渲染，不显示「无 HTML」之类的提示 |
| 正文为空（两者皆 null） | `此邮件没有正文内容` + 附件区（很多验证码邮件正文在附件或仅有主题） |
| 邮件超大（>2 MB HTML） | 先渲染前 512 KB + `[显示完整邮件（2.4 MB）]` 按钮 |
| 附件未下载（`downloadedAt === null`） | 卡片显示文件名和大小，图标带下载箭头，点击后拉取，期间卡片内 2px 进度条 |
| 账号是 `auth_error` 时打开旧邮件 | 顶部 `--warning-subtle` 条：`此账号授权已失效，内容可能不是最新的` + `[重新授权]` |

## 10. 三态规范（空 / 加载 / 错误）

### 10.1 加载：骨架 vs spinner 的判定规则

| 用 **骨架** | 用 **spinner** | 用 **进度条** |
| --- | --- | --- |
| 结构已知、位置固定的内容：邮件列表行、阅读区、账号表格、设置表单 | 结构未知或瞬时的操作：按钮内、测试连接、发送中 | 有确定进度：附件下载、批量同步 29 个账号、批量导入 |

**共同规则**

- 200ms 内能返回的**什么都不显示**（用 `useDeferredValue` 或延迟 200ms 才切换到 loading 态），否则会闪。
- 骨架必须与真实内容**行数、行高、圆角一致**，宽度用 3 档随机（`w-3/4` `w-1/2` `w-5/6`）避免整齐得像表格。
- 首屏列表骨架渲染 `Math.ceil(视口高度 / 行高)` 行，不多不少。
- 分页加载更多：底部 3 行骨架，不是 spinner。
- 所有 loading 容器 `aria-busy="true"`，完成后配一次 `aria-live="polite"` 的 `已加载 50 封邮件`。

### 10.2 每个屏幕的三态

| 屏幕 | 空态 | 加载态 | 错误态 |
| --- | --- | --- | --- |
| 邮件列表 | 图标 + `收件箱是空的` + `所有账号都没有新邮件` + `[立即同步]` | N 行骨架（按视口算） | 卡片：`无法加载邮件` + 错误码 + `[重试]`；**已缓存的数据继续显示**，错误只作为顶部一条横幅（TanStack Query 的 `isError && data` 分支） |
| 邮件列表（有筛选） | `没有符合条件的邮件` + 回显当前筛选 chip + `[清除筛选]` | 同上 | 同上 |
| 验证码视图 | `近 7 天没有验证码邮件` + `验证码会自动从主题和正文中识别` | 同上 | 同上 |
| 阅读区 | `选择一封邮件` + `或按 J / K 浏览` | 主题 2 行 + 6 条正文骨架 | 见 §4 |
| 搜索 | 未搜索：`搜索全部 29 个账号` + 语法提示（4 条示例）；无结果：`没有找到「xxx」` + `[清除筛选后重试]` + 拼写建议 | 结果区 8 行骨架 | `搜索失败` + `[重试]`；超时（>10s）单独文案 `搜索超时，试试缩小时间范围` |
| 账号列表 | `还没有添加账号` + `[添加账号]` + `[批量导入]`（导入是主路径，摆同等权重） | 4 张统计块骨架 + 6 行表格骨架 | 整页错误卡 + `[重试]` |
| 账号列表（有筛选） | `没有「需重新授权」状态的账号` + `[查看全部]` —— **这是好消息，用 `--success` 的对勾图标而不是灰色空盒子** | | |
| 设置 | 无空态 | 表单字段骨架（label 短条 + 控件长条） | 字段级：红边框 + 下方错误文字；页面级：顶部横幅 |
| 用户管理 | `只有你一个用户` + 说明文字（见 §8） | 3 行表格骨架 | 整页错误卡 |
| 撰写 | 无空态 | 打开时若在加载草稿：正文区骨架 | 发送失败：撰写窗保持打开 + 顶部红条 `发送失败：<原因>` + `[重试]`，**绝不丢失用户输入的内容** |
| 全局离线 | — | — | 顶部固定 28px 条 `离线 · 显示的是缓存内容`，恢复后自动消失并静默 refetch |

### 10.3 空态的写法规则

每个空态 = **图标 + 一句陈述 + 一句解释 + 0–2 个动作**。

- 图标：lucide 线性图标，96px（移动端 64px），`text-muted-foreground/40`。**不用插画。** 自托管工具不需要吉祥物。
- 陈述用中文陈述句，不用感叹号，不用「哎呀」「糟糕」这类拟人语气。
- 有动作时，主动作 `variant="default"`，次动作 `variant="ghost"`。
- 「筛选后无结果」和「本来就没有数据」必须是不同文案 —— 前者要给出清除筛选的路。
